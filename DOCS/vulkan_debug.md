# Vulkan Debug: Subnormal FP16 Bug in Q8_0 Matmul Shader

**Дата:** 24 июля 2026
**Статус:** Исправлено
**Коммит:** (следующий)

---

## Проблема

Vulkan backend (`--backend vulkan`) для Qwen2.5-0.5B Q8_0 генерировал мусор на выходе:

```
CPU:  "As an AI, I'm sorry for any inconvenience..."
VK:   "12398547689720234563"
```

## Диагностика

### Шаг 1: Локализация до первого токена

Сравнение hidden state после 24 слоёв на gen=0:

| Метрика | CPU | Vulkan (broken) | Разница |
|---------|-----|-----------------|---------|
| RMS | 1.9814 | 2.0406 | ~3% |
| Top-1 token | 151645 (13.94) | 16 (13.41) | Разный! |
| Top-2 token | 16 (13.63) | 151645 (12.89) | Поменялись |

После gen=1 разница RMS достигала 25% — модель уходила в неверное пространство токенов.

### Шаг 2: Тест отдельных matmul

- **token_embd.weight** (896×151936): CPU vs VK совпадают (`max_diff=0.0000`)
- **blk.0.attn_q.weight** (896×896): CPU vs VK различаются (`max_diff=0.418`)

### Шаг 3: Изоляция причины — сравнение шейдера и CPU

CPU NEON (`calm_quant.c:486`):
```c
float d = fp16_to_f32(row[b].d);  // табличный lookup
vacc = vfmaq_f32(vacc, x_lo, vmulq_f32(dv, wf_lo));
```

GPU шейдер (`shaders/q8_0_matmul.comp`):
```glsl
float fp16_to_fp32_u(uint h_bits) { ... }
float d = fp16_to_fp32_u(d_bits);
sum += d * (x0*w0 + x1*w1 + x2*w2 + x3*w3);
```

Разница в FMA-порядке не объясняла 0.418 max_diff. Подозрение пало на `fp16_to_fp32`.

### Шаг 4: Root Cause — Subnormal FP16 bug

Сравнение CPU vs GPU конверсии FP16→FP32:

| FP16 (hex) | CPU (правильно) | GPU (сломано) | Ошибка |
|------------|----------------|---------------|--------|
| 0x0001 (мин. субнормаль) | 2⁻²⁴ | 2⁻¹⁴ | **1024×** |
| 0x0040 (mant=64) | 2⁻¹⁸ | 2⁻²⁰ | **4×** |
| 0x03FF (макс. субнормаль) | ~2×2⁻¹⁵ | ~2×2⁻²³ | **256×** |

**Формула в шейдере была неверна:**
```glsl
// BUG: было
uint exp32 = uint(127 - 14 - s);  // WRONG

// FIX: должно быть
uint exp32 = uint(127 - 24 + s);  // CORRECT
```

### Шаг 5: Сколько субнормальных блоков в модели?

| Тензор | Блоков | Субнормальных | % |
|--------|--------|---------------|---|
| token_embd.weight | 4,254,208 | 0 | 0.000% |
| blk.0.attn_q.weight | 25,088 | 40 | 0.159% |
| blk.0.attn_output.weight | 25,088 | 88 | 0.351% |

`token_embd.weight` не имел субнормальных шкал — поэтому тест проходил идеально. Остальные тензоры имели 0.15-0.35% субнормальных блоков, которые через 24 слоя накапливали ошибку до 25% в hidden state RMS.

## Результат после фикса

| Метрика | До фикса | После фикса |
|---------|----------|-------------|
| max_diff CPU vs VK (Q weight) | 0.41819221 | **0.00001717** |
| Относительная ошибка | 50.5% | **0.0003%** |
| Gen=0 RMS diff | 3% | **1.6%** (нормально) |
| Вывод модели | "12398547689720234563" | "As an AI, please provide the best way..." |
| Осмысленность | Мусор | Связный английский |

Оставшаяся ошибка (1.6% RMS, 1.7e-5 max_diff) — это нормальные IEEE 754 различия между NEON FMA (fused multiply-add) и скалярными mul+add на GPU. Два разных бэкенда дают slightly разные, но одинаково корректные результаты.

## Вывод

**Vulkan бэкенд для Q8_0 matmul теперь работает корректно.** CPU и Vulkan дают different but equally valid continuations — как и ожидается от двух разных FP-пайплайнов, считающих одну и ту же математику разными путями.
